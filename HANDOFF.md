## 1. Требования владельца продукта (не нарушать)

1. Продукт — сервис для работы с таблицами уровня базового Google Sheets, стиль macOS, тёмная тема.
2. **Никаких KPI-панелей, дашбордов и визуализации метрик.** Они были реализованы и удалены по требованию владельца. Не возвращать.
3. **Без S3 / MinIO.** Файлы отдаются через API потоком и на диск не пишутся (см. раздел 4.6 плана).
4. Готовые библиотеки предпочтительнее собственных реализаций.
5. Интеграция с таблицами PostgreSQL обязательна.
6. Бэкенд — Python FastAPI.
7. Без явной просьбы не делать коммиты и push. На момент передачи в git ничего не закоммичено; удалённый репозиторий: `git@github.com:Nezhirn/thule-sheets.git`.

## 5. Ключевые решения и подводные камни

Это всё найдено на практике; при изменениях не наступать повторно.

1. **Префикс `THULE_` у всех переменных окружения.** В шелле пользователя есть чужой `DATABASE_URL`; без префикса настройки и тесты уходили в чужую базу.
2. **Тёмная тема Univer инвертирует цвета холста** (`darkMode: true`). Цвета в снапшотах хранятся «светлыми» (как в Excel) и экспортируются как есть. Палитра в тулбаре показывает цвета через `displayColor()` (та же матрица инверсии). Не передавать `darkBlueTheme` вместе с `darkMode`: будет двойная инверсия.
3. **Синхронизация (`apps/web/src/editor/sync.ts`):**
   - Чужие мутации применяются с `{ fromCollab: true }`, **не** с `onlyLocal`: движок формул пропускает `onlyLocal`-мутации, и пересчёт формул у пиров не происходил.
   - В сеть уходят только мутации текущей книги (`params.unitId`), `doc.*` (посимвольный ввод во встроенном редакторе ячейки) и `formula.mutation.*` отсекаются. Сервер дополнительно отклоняет `doc.*`.
   - Порядок задаёт сервер (ревизия на строке `workbooks` с `FOR UPDATE`). Абсолютные мутации (`set-range-values`, ширины, высоты, имя листа) при гонке переигрываются поверх; для остальных при конфликте выполняется пересборка книги из снапшота и журнала.
   - Идемпотентность: каждая пачка несёт `opId`, на сервере уникальный `(workbook_id, op_id)`; после переподключения клиент узнаёт свою пачку в журнале.
4. **Сортировка в `pg/catalog.py`:** в `SELECT` колонки приводятся к `::text` под теми же именами, поэтому `ORDER BY` обязан ссылаться на `t."col"` (алиас таблицы), иначе сортировка текстовая. Есть регрессионный тест.
5. **SQL-консоль:** запрос выполняется через prepared statement (несколько выражений отклоняются) в `READ ONLY`-транзакции. Это не защищает от функций с побочными эффектами (`pg_terminate_backend`, `dblink`), поэтому подключаться нужно ролью с минимальными правами (подсказка есть в UI).
6. **SSRF:** `THULE_ALLOW_PRIVATE_DB_HOSTS=false` по умолчанию; проверка выполняется до подключения (между проверкой и соединением возможен DNS rebinding, задача ниже).
7. **CSV-экспорт** экранирует строки, начинающиеся с `= + - @` (CSV-инъекция). Формулы из импортируемого CSV сохраняются как текст.
8. **Glide Data Grid заменена на AG Grid Community 36** (MIT): стабильная Glide 6.0.3 не поддерживает React 19.
9. **`pkill -f <шаблон>` в Bash-инструменте убивает собственный шелл**, если шаблон есть в командной строке. Останавливать процессы по порту: `ss -ltnp | grep :8010`, затем `kill <pid>`.
10. **Ввод кириллицы через эмуляцию клавиатуры в headless Camoufox** даёт в редакторе Univer перевёрнутый текст с удвоенными символами. Это артефакт эмуляции (латиница вводится корректно). Для проверок кириллицы использовать строку формул или Facade API.
11. Первый расчёт формул после открытия свежего шаблона занимает ~1–2 с (кэшированных значений ещё нет); после первого сохранения снапшота значения хранятся.
12. Univer: стандартные шапка, тулбар, строка формул и футер отключены, команды вызываются через `executeCommand` (`editor/actions.ts`). ID команд проверены по исходникам Univer 1.2.0. Версии всех `@univerjs/*` зафиксированы точно (1.2.0), обновлять только вместе.

Ревью выполнено двумя независимыми проходами: бэкенд/безопасность и фронтенд/realtime.
Находки проверялись по исходникам и живым запросам, не по описанию.

### Исправлено

| Область | Проблема | Исправление |
|---|---|---|
| Импорт XLSX | 4,8 МБ файл разворачивался в 3,7 ГБ RSS и 37 с CPU до проверки лимита | Проверка zip-архива и объявленных размеров листов в lazy-режиме до разбора; бюджет считается по всем итерируемым ячейкам. Замер: 31 МБ, 5 мс, `ConversionError` |
| Тело запроса | multipart и JSON буферизовались целиком до проверки лимита | ASGI-middleware с лимитом `THULE_MAX_REQUEST_MB` до маршрутизации и счётчиком фактических байт; `LoginIn.password` ограничен 200 символами |
| Снапшоты | устаревший `rev` возвращал 200 и молча отбрасывался | `409 Snapshot is stale`; клиент по 409 пересобирает книгу из снапшота |
| Шаринг | внешний получатель доступа мог приглашать других и видеть состав пространства | приглашение/отзыв требуют роли editor в рабочем пространстве; внешний пользователь видит только свою запись |
| WebSocket | роль фиксировалась при подключении | роль перепроверяется в `_append_ops` на каждой пачке; при отзыве доступа приходит `Read-only access` |
| Redis | ошибка pub/sub роняла запрос или сокет и оставляла presence-мусор | все вызовы Redis перехватывают ошибки и деградируют к локальной доставке |
| SQL-консоль | одно огромное значение могло исчерпать память до проверки лимита строк | потоковое чтение с бюджетом `THULE_DB_QUERY_BYTE_LIMIT` |
| Экспорт | клиентский снапшот не ограничивался по числу ячеек | лимит `MAX_CELLS` для XLSX и CSV |
| CSV | поле больше 128 КБ давало 500 | лимит поля и `ConversionError` вместо необработанного `_csv.Error` |
| Общий доступ к БД | viewer мог инициировать исходящее подключение с сохранённым паролем | `/connections/{id}/test` требует editor |
| Frontend sync | ответ сервера `error` навсегда блокировал отправку (inflight не очищался) | ошибка очищает пачку, показывает состояние и запускает пересборку; пачки ограничены по байтам |
| Frontend sync | неудачное применение чужой мутации пропускалось, ревизия росла, расхождение попадало в снапшот | `false`/исключение от `syncExecuteCommand` запускает пересборку, снапшот не сохраняется |
| Frontend | ошибка `catchUp()` оставляла редактор навсегда со спиннером | `start()` не блокируется, редактор открывается, повтор синхронизации после `hello` |
| Frontend | «Строку выше» и «Столбец слева» падали без параметра | передаётся `{ value: 1 }` |
| Frontend | переключение избранного пересоздавало редактор | эффект зависит от id книги, а не от объекта запроса |
| Frontend | «заканчивается на» работало как «содержит» | добавлен `ends_with` на бэкенде и в маппинге AG Grid |
| Frontend | диапазонный фильтр с одной границей отправлял строку `null` | каждая граница добавляется только при наличии значения |
| Frontend | presence отправлялся на каждое событие выделения | троттлинг 120 мс и пропуск неизменившихся выделений |
| Frontend | пересборка при ошибке не повторялась, опрос шёл каждые 150 мс | экспоненциальный backoff и повтор после переподключения |

### Осталось (приоритет)

1. **SSRF / DNS rebinding (High).** Проверка адреса и подключение выполняются разными
   резолвами. Нужно подключаться к уже проверенному IP, сохраняя имя хоста для TLS
   (`server_hostname`), либо установить резолвер на уровне asyncpg.
2. **Отзыв сессий (Medium).** JWT живёт 7 дней, logout удаляет только cookie. Нужен
   `token_version` пользователя или denylist `jti` в Redis.
3. **Rate limiting (Medium).** Нет ограничений на `/auth/*`, `/connections/*/query`
   и WebSocket-сообщения.
4. **Журнал операций (Medium).** `GET /ops` не пагинируется и не чистится после
   снапшотов. Нужны `limit`/`next_rev` и фоновая компактизация.
5. **Лимит размера таблицы БД (Medium).** `rows` по-прежнему может вернуть много
   текстовых данных: лимит строк есть, лимита байт нет.
6. **Prod-конфигурация (Medium).** `THULE_ENVIRONMENT` по умолчанию `dev`; при
   забытой переменной приложение стартует с dev-секретами. Нужен fail-fast.
7. **Один глобальный lock пулов (Medium).** Недоступная внешняя БД блокирует
   подключения всех пользователей до таймаута.
8. **Аудит подключений к БД (Medium).** Создание, изменение и удаление подключения
   не пишутся в `audit_log`.
9. **Presence-сообщения (Medium).** Сервер принимает `selection` до 4 МБ; нужен
   отдельный лимит и троттлинг на стороне сервера.
10. **Frontend-тесты (High для дальнейших изменений).** Нет Vitest для `sync.ts`
    и Playwright-сценария «две вкладки». Исправления синхронизации проверены
    вручную, но регрессии пока ловятся только глазами.
11. **Бандл (Low).** `WorkbookPage` — 7,6 МБ (1,9 МБ gzip); нужен `manualChunks`
    для `@univerjs/*`.
12. **Мелочи (Low).** Проверка Origin за прокси, `updated_at` при восстановлении
    версии, уведомление пиров об удалении книги, `RESET ALL` при возврате
    соединения в пул, health-check с проверкой БД и Redis, `*.egg-info/` в
    `.gitignore`.
