# Thule Sheets — передача задач

Документ для следующего исполнителя. Описывает текущее состояние проекта, принятые решения, известные проблемы и оставшиеся задачи по приоритету.

## 1. Требования владельца продукта (не нарушать)

1. Продукт — сервис для работы с таблицами уровня базового Google Sheets, стиль macOS, тёмная тема.
2. **Никаких KPI-панелей, дашбордов и визуализации метрик.** Они были реализованы и удалены по требованию владельца. Не возвращать.
3. **Без S3 / MinIO.** Файлы отдаются через API потоком и на диск не пишутся (см. раздел 4.6 плана).
4. Готовые библиотеки предпочтительнее собственных реализаций.
5. Интеграция с таблицами PostgreSQL обязательна.
6. Бэкенд — Python FastAPI.
7. Без явной просьбы не делать коммиты и push. Удалённый репозиторий: `git@github.com:Nezhirn/thule-sheets.git`.
8. **Сохранение только явное.** Книги и таблицы БД не сохраняются автоматически и не синхронизируются в реальном времени: правки живут в браузере, пока пользователь не нажмёт «Сохранить» (или Ctrl+S). Совместное редактирование в реальном времени (WebSocket, журнал операций, Redis, присутствие) удалено по требованию владельца. Не возвращать.

## 5. Ключевые решения и подводные камни

Это всё найдено на практике; при изменениях не наступать повторно.

1. **Префикс `THULE_` у всех переменных окружения.** В шелле пользователя есть чужой `DATABASE_URL`; без префикса настройки и тесты уходили в чужую базу.
2. **Тёмная тема Univer инвертирует цвета холста** (`darkMode`, по умолчанию включён; пользователь переключает его через `editor/inversion.ts`, `univerAPI.toggleDarkMode`, ключ `thule.sheet.inverted`). Цвета в снапшотах хранятся «светлыми» (как в Excel) и экспортируются как есть. Палитра в тулбаре показывает цвета через `displayColor()` (та же матрица инверсии), когда инверсия включена. Не передавать `darkBlueTheme` вместе с `darkMode`: будет двойная инверсия.
3. **Сохранение книги:**
   - `workbooks.rev` увеличивается при каждом сохранении. Клиент отправляет `PUT /snapshot` с `base_rev` — ревизией, с которой открыта его копия. Если книгу успели сохранить из другой вкладки или другим пользователем, сервер отвечает 409 с `rev`, `saved_at`, `saved_by`; клиент предлагает «Перезаписать» (`force: true`) или «Загрузить их версию». Восстановление версии тоже увеличивает `rev`.
   - Признак несохранённых правок (`editor/changes.ts`) ставится по мутациям Univer текущей книги; `doc.*` (ввод во встроенном редакторе ячейки), `formula.mutation.*` (результаты пересчёта) и мутации с `onlyLocal` не учитываются, иначе книга «пачкается» сразу после открытия.
   - Снапшот (`workbook.save()`) содержит вычисленные значения формул (`v`), поэтому экспорт CSV из интерфейса выдаёт значения. Сервер формулы не вычисляет: у книги, импортированной без закэшированных значений и ни разу не сохранённой, формульные ячейки в CSV пустые.
   - Навигация внутри приложения блокируется через `useBlocker`, поэтому роутер — data router (`createBrowserRouter`), не `BrowserRouter`.
   - Строка книги блокируется через `_lock_workbook()` (`FOR UPDATE` + `populate_existing`). Без `populate_existing` объект, уже загруженный проверкой доступа, сохраняет старый `rev`, и два одновременных сохранения проходят оба. Тест: `test_save_waiting_for_lock_sees_concurrent_save`.
   - Запрос `['workbook', id]` в `WorkbookPage` нельзя менять, пока редактор открыт (новый объект пересоздаёт Univer и теряет несохранённые правки), поэтому «Избранное» хранится в отдельном состоянии, а `gcTime: 0` не даёт открыть книгу из устаревшего кэша.
   - Миграция `c41f7a9d2e10` останавливается, если у книги есть операции новее снапшота (`head_rev > snapshot_rev`), вместо того чтобы молча их потерять.
4a. **Таблица БД в Univer (`db/sheetController.ts`):**
   - Строки листа = окно результата запроса (offset), блоки по 500 строк догружаются по операциям прокрутки. Ниже данных держится 20 пустых строк для ввода новых записей.
   - Запрещённые правки (PK, вычисляемые колонки, формулы, незагруженные строки, любые структурные мутации — вставка/удаление строк и колонок, объединения, числовые форматы) отменяются в `BeforeSheetEditStart` / `BeforeCommandExecute` до применения.
   - Подсветка правок ставится внутренними мутациями `set-range-values` с `isOverrideStyle`; они не попадают в историю отмены.
   - Сохранение (`POST …/rows/apply`): один запрос за раз; пока он идёт, правки отклоняются. После успеха локальные изменения сбрасываются до перечитывания таблицы; если перечитать не удалось, лист заблокирован до «Обновить» (иначе повторное сохранение вставило бы строки дважды).
   - Удаление отправляет всю строку в `expected`: строку, изменённую или удалённую в базе после загрузки, сервер не удаляет и отвечает 409, клиент снимает пометку и показывает текущие значения.
   - Если `count(*)` не уложился в таймаут, число строк — оценка `reltuples` (без учёта фильтров). Граница «данные / новые строки» уточняется по загруженным блокам (`refineTotal`); «Строка» ищет настоящий конец удвоением и бисекцией (`seekEnd`), ввод новых строк до этого запрещён.
   - Univer обрезает диапазоны проверки данных по размеру листа: при росте листа `setRowCount()` растягивает правила (выпадающие списки enum/boolean).
   - **Баг Univer 1.2:** facade-события `SelectionChanged` и `Scroll` не подключаются для книг, созданных после первой отрисовки. Выделение и прокрутка отслеживаются через `CommandExecuted` (`sheet.operation.set-selections`, `sheet.operation.set-scroll`).
   - `customizeColumnHeader` доступен только после создания рендера книги (несколько кадров), поэтому вызывается с повторами.
   - Текстовые колонки получают числовой формат `@` (иначе Univer превращает «007» в 7 и даты в серийные числа); зелёные метки «число как текст» отключены опцией `disableTextFormatMark` только для таблиц БД.
4. **Сортировка в `pg/catalog.py`:** в `SELECT` колонки приводятся к `::text` под теми же именами, поэтому `ORDER BY` обязан ссылаться на `t."col"` (алиас таблицы), иначе сортировка текстовая. Есть регрессионный тест.
5. **SQL-консоль:** запрос выполняется через prepared statement (несколько выражений отклоняются) в `READ ONLY`-транзакции. Это не защищает от функций с побочными эффектами (`pg_terminate_backend`, `dblink`), поэтому подключаться нужно ролью с минимальными правами (подсказка есть в UI).
6. **SSRF:** `THULE_ALLOW_PRIVATE_DB_HOSTS=false` по умолчанию; проверка выполняется до подключения (между проверкой и соединением возможен DNS rebinding, задача ниже).
7. **CSV-экспорт** экранирует строки, начинающиеся с `= + - @` (CSV-инъекция). Формулы из импортируемого CSV сохраняются как текст.
8. **Glide Data Grid заменена на AG Grid Community 36** (MIT): стабильная Glide 6.0.3 не поддерживает React 19.
9. **`pkill -f <шаблон>` в Bash-инструменте убивает собственный шелл**, если шаблон есть в командной строке. Останавливать процессы по порту: `ss -ltnp | grep :8010`, затем `kill <pid>`.
10. **Ввод кириллицы через эмуляцию клавиатуры в headless Camoufox** даёт в редакторе Univer перевёрнутый текст с удвоенными символами. Это артефакт эмуляции (латиница вводится корректно). Для проверок кириллицы использовать строку формул или Facade API.
11. Первый расчёт формул после открытия свежего шаблона занимает ~1–2 с (кэшированных значений ещё нет); после первого сохранения снапшота значения хранятся.
12. Univer: стандартные шапка, тулбар, строка формул и футер отключены, команды вызываются через `executeCommand` (`editor/actions.ts`). ID команд проверены по исходникам Univer 1.2.0. Версии всех `@univerjs/*` зафиксированы точно (1.2.0), обновлять только вместе.

16. Сводные таблицы и печать / PDF — вне MVP, только после согласования с владельцем.

## 7. Критерии готовности для каждой задачи

- Бэкенд: `pytest -q`, `ruff check`, `mypy app` без ошибок; новые эндпоинты покрыты тестами.
- Фронтенд: `tsc --noEmit` и `vite build` без ошибок; изменения UI проверены в браузере.
- Миграции применяются и откатываются (`alembic upgrade head` / `downgrade base`).
- В коде, комментариях, коммитах и документации — нейтральный профессиональный язык.
