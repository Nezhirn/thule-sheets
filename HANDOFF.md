# Thule Sheets — передача задач

Документ для следующего исполнителя. Описывает текущее состояние проекта, принятые решения, известные проблемы и оставшиеся задачи по приоритету.

Исходная спецификация: `thule-sheets-plan.md` (раздел 4.6 «Файлы» написан владельцем продукта и обязателен к исполнению).

## 1. Требования владельца продукта (не нарушать)

1. Продукт — сервис для работы с таблицами уровня базового Google Sheets, стиль macOS, тёмная тема.
2. **Никаких KPI-панелей, дашбордов и визуализации метрик.** Они были реализованы и удалены по требованию владельца. Не возвращать.
3. **Без S3 / MinIO.** Файлы отдаются через API потоком и на диск не пишутся (см. раздел 4.6 плана).
4. Готовые библиотеки предпочтительнее собственных реализаций.
5. Интеграция с таблицами PostgreSQL обязательна.
6. Бэкенд — Python FastAPI.
7. Без явной просьбы не делать коммиты и push. На момент передачи в git ничего не закоммичено; удалённый репозиторий: `git@github.com:Nezhirn/thule-sheets.git`.

## 4. Запуск для разработки

```bash
cd ~/OpenCode_Dir/thule-sheets
docker compose up -d postgres redis

# бэкенд
cd apps/api
python3.12 -m venv .venv && .venv/bin/pip install -e '.[dev]'   # venv уже создан
.venv/bin/alembic upgrade head
THULE_REDIS_URL=redis://127.0.0.1:56379/0 THULE_ALLOW_PRIVATE_DB_HOSTS=true \
  .venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8010

# фронтенд (проксирует /api и WebSocket на 8010)
cd apps/web && npm install && npx vite          # http://127.0.0.1:5180

# проверки
cd apps/api && .venv/bin/pytest -q && .venv/bin/ruff check app tests && .venv/bin/mypy app --ignore-missing-imports
cd apps/web && npx tsc --noEmit && npx vite build
```

Тесты используют отдельную базу `thule_sheets_test` в том же контейнере (создана). Для ручной проверки PostgreSQL-интеграции есть демо-база `demo_shop` (customers, products, orders с enum, view sales_by_product): host 127.0.0.1, port 55432, user/password `thule`/`thule`.

На момент передачи могут быть запущены фоновые процессы uvicorn (8010) и vite (5180).

## 5. Ключевые решения и подводные камни

Это всё найдено на практике; при изменениях не наступать повторно.

1. **Префикс `THULE_` у всех переменных окружения.** В шелле пользователя есть чужой `DATABASE_URL`; без префикса настройки и тесты уходили в чужую базу.
2. **Тёмная тема Univer инвертирует цвета холста** (`darkMode: true`). Цвета в снапшотах хранятся «светлыми» (как в Excel) и экспортируются как есть. Палитра в тулбаре показывает цвета через `displayColor()` (та же матрица инверсии). Не передавать `darkBlueTheme` вместе с `darkMode`: будет двойная инверсия.
3. **Синхронизация (`apps/web/src/editor/sync.ts`):**
   - Чужие мутации применяются с `{ fromCollab: true }`, **не** с `onlyLocal`: движок формул пропускает `onlyLocal`-мутации, и пересчёт формул у пиров не происходил.
   - В сеть уходят только мутации текущей книги (`params.unitId`), `doc.*` (посимвольный ввод во встроенном редакторе ячейки) и `formula.mutation.*` отсекаются. Сервер дополнительно отклоняет `doc.*`.
   - Порядок задаёт сервер (ревизия на строке `workbooks` с `FOR UPDATE`). Абсолютные мутации (`set-range-values`, ширины, высоты, имя листа) при гонке переигрываются поверх; для остальных при конфликте выполняется пересборка книги из снапшота и журнала.
   - Идемпотентность: каждая пачка несёт `opId`, на сервере уникальный `(workbook_id, op_id)`; после переподключения клиент узнаёт свою пачку в журнале.
4. **Сортировка в `pg/catalog.py`:** в `SELECT` колонки приводятся к `::text` под теми же именами, поэтому `ORDER BY` обязан ссылаться на `t."col"` (алиас таблицы), иначе сортировка текстовая. Есть регрессионный тест.
5. **SQL-консоль:** запрос выполняется через prepared statement (несколько выражений отклоняются) в `READ ONLY`-транзакции. Это не защищает от функций с побочными эффектами (`pg_terminate_backend`, `dblink`), поэтому подключаться нужно ролью с минимальными правами (подсказка есть в UI).
6. **SSRF:** `THULE_ALLOW_PRIVATE_DB_HOSTS=false` по умолчанию; проверка выполняется до подключения (между проверкой и соединением возможен DNS rebinding, задача ниже).
7. **CSV-экспорт** экранирует строки, начинающиеся с `= + - @` (CSV-инъекция). Формулы из импортируемого CSV сохраняются как текст.
8. **Glide Data Grid заменена на AG Grid Community 36** (MIT): стабильная Glide 6.0.3 не поддерживает React 19.
9. **`pkill -f <шаблон>` в Bash-инструменте убивает собственный шелл**, если шаблон есть в командной строке. Останавливать процессы по порту: `ss -ltnp | grep :8010`, затем `kill <pid>`.
10. **Ввод кириллицы через эмуляцию клавиатуры в headless Camoufox** даёт в редакторе Univer перевёрнутый текст с удвоенными символами. Это артефакт эмуляции (латиница вводится корректно). Для проверок кириллицы использовать строку формул или Facade API.
11. Первый расчёт формул после открытия свежего шаблона занимает ~1–2 с (кэшированных значений ещё нет); после первого сохранения снапшота значения хранятся.
12. Univer: стандартные шапка, тулбар, строка формул и футер отключены, команды вызываются через `executeCommand` (`editor/actions.ts`). ID команд проверены по исходникам Univer 1.2.0. Версии всех `@univerjs/*` зафиксированы точно (1.2.0), обновлять только вместе.

## 6. Оставшиеся задачи

### P0 — довести до рабочего релиза

1. **Проверить сборку Docker-образа** (`docker build -t thule-sheets:dev .`) и запуск `docker compose --profile app up` с заполненным `.env`. Убедиться, что SPA раздаётся из FastAPI, работают WebSocket и миграции при старте.
2. **Обновить `thule-sheets-plan.md`:** убрать упоминания KPI-панели и дашборда (раздел 4.1 «Панель KPI», этап 6 «Дашборд и графики», строку про графики в чек-листе), отразить замену Glide → AG Grid. Раздел 4.6 не трогать.
3. **README.md** в корне: назначение, запуск для разработки, переменные окружения, деплой.
4. **Ручная проверка в браузере** сценариев, которые ещё не прогонялись: импорт XLSX через UI, экспорт XLSX/CSV через меню «Файл», диалоги «Поделиться» и «История версий» (восстановление версии при открытой второй вкладке), вставка/удаление строк при двух открытых вкладках (путь пересборки), фильтр и вставка строки в AG Grid, режим только для чтения у пользователя-читателя.

### P1 — качество и надёжность

5. **Фронтенд-тесты:** Vitest для `editor/sync.ts` (упорядочивание ревизий, дедупликация, переигрывание абсолютных мутаций, путь пересборки) и Playwright для сценария «две вкладки редактируют одну книгу».
6. **CI** (GitHub Actions): ruff, mypy, pytest с сервисами Postgres/Redis, tsc, vite build.
7. **Формульный worker Univer:** сейчас движок формул работает в основном потоке. Проверить на листах от 100k ячеек и при необходимости включить `workerURL` (в старом PoC пересчёт через worker не срабатывал, причину не выясняли).
8. **Размер бандла:** чанк редактора ~8 МБ (2 МБ gzip). Вырезать неиспользуемые локали Univer, разделить пресеты.
9. **Защита от DNS rebinding** при подключении к внешним БД: подключаться к уже проверенному IP (с сохранением имени хоста для TLS `server_hostname`).
10. **Rate limiting** на `/api/auth/*` и `/connections/*/query` (Redis уже есть).
11. **Компактизация журнала операций:** удалять `workbook_ops` старше последнего снапшота плюс запас (например, 7 дней), фоновой задачей.

### P2 — функциональность из плана

12. Связанные диапазоны «таблица БД ⇄ лист» с обновлением по кнопке и по расписанию (план, раздел 5.4). Сейчас есть только разовая вставка результата запроса.
13. Пользовательская функция формул вида `=PG("conn", "select …")` (регистрация custom function в Univer).
14. Локализованные имена функций в строке формул (`=СУММ`), хранение канонических английских.
15. Отображение курсоров и выделений других пользователей на холсте (сейчас только аватары с подсказкой «Имя — Лист!A1»).
16. Редактор FK-колонок в AG Grid с поиском по связанной таблице; редактор дат с календарём.
17. Сводные таблицы и печать / PDF — вне MVP, только после согласования с владельцем.
